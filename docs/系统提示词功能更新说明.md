## 🎯 核心功能

### 发送给模型的格式
系统提示词使用 OpenAI API 标准格式，作为 messages 数组的第一条消息：

```json
[
  {"role": "system", "content": "你是一个专业的编程助手..."},
  {"role": "user", "content": "用户消息"},
  {"role": "assistant", "content": "AI回复"}
]
```

### 数据存储
系统提示词存储在会话配置中：

```python
class SessionConfig(BaseModel):
    source_name: Optional[str] = None
    models: List[str] = []
    temperature: float = 0.7
    top_p: float = 1.0
    system_prompt: Optional[str] = None  # 新增字段
```

### API 接口
更新会话配置时包含系统提示词：

```http
PUT /api/sessions/{session_id}/config
{
  "source_name": "OpenRouter",
  "models": ["qwen/qwen-2.5-7b-instruct"],
  "temperature": 0.7,
  "top_p": 1.0,
  "system_prompt": "你是一个专业的编程助手..."
}
```

## 🔧 技术细节

### 调研结果：系统提示词的实现方式

通过调研主流 AI 对话应用，系统提示词的标准实现方式为：

1. **OpenAI API 格式**
   - 使用 `role: "system"` 的消息
   - 放在消息数组的第一位
   - 影响整个对话的上下文

2. **会话级别配置**
   - 每个会话独立配置
   - 持久化存储
   - 可随时修改

3. **预设模板 + 自定义**
   - 提供常用模板快速选择
   - 支持完全自定义
   - 允许在模板基础上修改

4. **优先级策略**
   - 会话级配置优先
   - 全局配置作为备用
   - 无配置时使用模型默认

## ⚠️ 注意事项

1. **Token 消耗**
   - 系统提示词会计入每次请求的 Token
   - 建议保持在 100-300 字以内

2. **模型差异**
   - 不同模型对系统提示词的遵循程度不同
   - GPT-4 效果最好，其他模型因情况而异

3. **向后兼容**
   - 保留了 Session.system_prompt 字段
   - 旧会话会自动使用 session_config.system_prompt

4. **实时生效**
   - 修改后仅对新消息生效
   - 已有的对话历史不受影响
