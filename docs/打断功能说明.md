# 打断功能说明

## 功能概述

新增了打断当前 AI 回答的功能，让用户可以随时停止 AI 的生成过程，提升交互的灵活性和控制感。

## 功能特性

### 1. 智能发送/停止按钮

发送按钮根据当前状态自动切换功能：

#### 正常状态（未发送）
- **外观**：紫色渐变背景
- **图标**：纸飞机图标 ✈️
- **功能**：发送消息
- **启用条件**：输入框有内容

#### 发送中状态
- **外观**：红色渐变背景 + 脉冲动画
- **图标**：停止图标 ⏹️
- **功能**：停止生成
- **启用条件**：始终可点击

### 2. 多种打断方式

#### 方式一：点击停止按钮
1. AI 正在生成回答时
2. 点击红色的停止按钮
3. 立即中断生成
4. 显示提示："已停止生成"

#### 方式二：直接输入新消息
1. AI 正在生成回答时
2. 在输入框输入新的消息
3. 按回车或点击发送按钮
4. 自动打断当前回答
5. 发送新消息

#### 方式三：语音识别自动发送
1. AI 正在生成回答时
2. 使用语音输入新消息
3. 语音识别完成后自动发送
4. 自动打断当前回答
5. 发送新消息

### 3. 打断后的行为

#### 已生成的内容
- **保留**：已经生成的部分内容会保留在对话中
- **可见**：用户可以看到打断前生成的内容
- **可操作**：可以复制、编辑、删除

#### 请求状态
- **立即取消**：使用 AbortController 取消网络请求
- **资源释放**：释放所有相关资源
- **状态重置**：恢复到可以发送新消息的状态

#### 用户反馈
- **提示信息**：显示"已停止生成"
- **按钮恢复**：停止按钮变回发送按钮
- **输入可用**：可以立即输入新消息

## 使用场景

### 场景 1：回答不满意
```
用户：介绍一下 Python
AI：Python 是一种高级编程语言...（开始长篇大论）
用户：（觉得太啰嗦）→ 点击停止按钮
用户：简单介绍 Python 的特点
```

### 场景 2：问题问错了
```
用户：如何学习 Java？
AI：学习 Java 需要...（开始回答）
用户：（发现问错了）→ 输入"如何学习 Python？"
系统：自动打断 Java 的回答，开始回答 Python
```

### 场景 3：语音纠正
```
用户：（语音）"介绍一下机器学习"
AI：机器学习是...（开始回答）
用户：（语音）"等等，我想问深度学习"
系统：自动打断，开始回答深度学习
```

### 场景 4：多模型对比
```
用户：写一个排序算法
AI：（多个模型同时生成）
用户：（看到第一个模型的回答就够了）→ 点击停止
系统：停止所有模型的生成
```

## 技术实现

### 核心机制

#### AbortController
```javascript
// 创建控制器
abortController.value = new AbortController()

// 发送请求时传入 signal
fetch('/api/chat', {
  signal: abortController.value.signal
})

// 取消请求
abortController.value.abort()
```

#### 状态管理
```javascript
// 发送状态
const isSending = ref(false)

// 控制器引用
const abortController = ref(null)

// 打断函数
function stopCurrentResponse() {
  if (abortController.value) {
    abortController.value.abort()
    abortController.value = null
  }
  isSending.value = false
  isTyping.value = false
}
```

#### 智能发送
```javascript
async function handleSendMessage() {
  // 如果正在发送，则打断
  if (isSending.value) {
    stopCurrentResponse()
    return
  }
  
  // 否则正常发送
  // ...
}
```

### 错误处理

#### AbortError 识别
```javascript
catch (error) {
  if (error.name === 'AbortError') {
    // 用户主动取消，不显示错误
    showNotification('已停止生成', 'info')
  } else {
    // 真正的错误
    showNotification('发送失败: ' + error.message, 'error')
  }
}
```

#### 资源清理
```javascript
finally {
  isSending.value = false
  isTyping.value = false
  abortController.value = null
  modelMessages = []
}
```

## 注意事项

### 1. 网络延迟
- 打断请求可能有轻微延迟（通常 < 100ms）
- 已发送到服务器的数据可能仍会被处理

### 2. 内容保留
- 打断时已生成的内容会保留
- 如果不需要，可以手动删除

### 3. 多模型场景
- 打断会停止所有正在生成的模型
- 已生成的部分内容会按模型分别保留

### 4. 连续操作
- 可以连续多次打断和发送
- 每次操作都会创建新的 AbortController
