# 推荐的项目结构

## 当前问题

当前所有 API 路由（2000+ 行）都在 `backend/api/routes.py` 一个文件中，导致：
- ❌ 文件过大，难以维护
- ❌ 代码查找困难
- ❌ 多人协作容易冲突
- ❌ 不符合单一职责原则

## 推荐结构

### 方案 1：按功能模块拆分（推荐）

```
backend/
├── api/
│   ├── __init__.py
│   ├── models.py              # 所有 Pydantic 模型
│   └── routes/
│       ├── __init__.py        # 汇总所有路由
│       ├── config.py          # 配置相关 API (~200 行)
│       │   ├── GET  /config
│       │   ├── POST /config/switch
│       │   ├── POST /config/add
│       │   ├── POST /config/update
│       │   └── DELETE /config/source/{name}
│       │
│       ├── chat.py            # 聊天相关 API (~300 行)
│       │   ├── POST /chat
│       │   └── POST /chat/regenerate
│       │
│       ├── recording.py       # 录音相关 API (~150 行)
│       │   ├── GET  /recording/status
│       │   ├── POST /recording/start
│       │   └── POST /recording/stop
│       │
│       ├── sessions.py        # 会话管理 API (~400 行)
│       │   ├── GET    /sessions
│       │   ├── POST   /sessions
│       │   ├── GET    /sessions/{id}
│       │   ├── POST   /sessions/{id}/switch
│       │   ├── PUT    /sessions/{id}/title
│       │   ├── PUT    /sessions/{id}/config
│       │   ├── DELETE /sessions/{id}
│       │   └── POST   /sessions/batch-delete
│       │
│       └── messages.py        # 消息管理 API (~300 行)
│           ├── PUT    /messages/{id}
│           ├── DELETE /messages/{id}
│           ├── POST   /messages/batch-delete
│           └── POST   /messages/insert-system-prompt
│
├── services/              # 业务逻辑层
│   ├── audio_recorder.py
│   ├── streaming_asr.py
│   └── session_storage.py
│
└── utils/                 # 工具函数
    ├── logger.py
    └── chat_logger.py
```

### 方案 2：按资源拆分（RESTful 风格）

```
backend/
├── api/
│   ├── __init__.py
│   ├── models.py
│   └── routes/
│       ├── __init__.py
│       ├── config_routes.py      # /config/*
│       ├── chat_routes.py        # /chat/*
│       ├── recording_routes.py   # /recording/*
│       ├── session_routes.py     # /sessions/*
│       └── message_routes.py     # /messages/*
```

## 实现示例

### `backend/api/routes/__init__.py`

```python
"""
API 路由汇总
"""
from fastapi import APIRouter

from .config import router as config_router
from .chat import router as chat_router
from .recording import router as recording_router
from .sessions import router as sessions_router
from .messages import router as messages_router

# 创建主路由器
router = APIRouter()

# 注册子路由
router.include_router(config_router, prefix="/config", tags=["配置管理"])
router.include_router(chat_router, prefix="/chat", tags=["聊天"])
router.include_router(recording_router, prefix="/recording", tags=["录音"])
router.include_router(sessions_router, prefix="/sessions", tags=["会话管理"])
router.include_router(messages_router, prefix="/messages", tags=["消息管理"])
```

## 迁移步骤

### 1. 创建新的目录结构

```bash
mkdir -p backend/api/routes
touch backend/api/routes/__init__.py
touch backend/api/routes/config.py
touch backend/api/routes/chat.py
touch backend/api/routes/recording.py
touch backend/api/routes/sessions.py
touch backend/api/routes/messages.py
```

### 2. 逐个迁移路由

从 `routes.py` 中复制相关路由到对应的文件：

1. **config.py**: 所有 `/config/*` 路由
2. **chat.py**: `/chat` 和 `/chat/regenerate`
3. **recording.py**: `/recording/*` 路由
4. **sessions.py**: `/sessions/*` 路由
5. **messages.py**: `/messages/*` 路由

### 3. 处理共享状态

将全局变量移到合适的位置：

```python
# backend/api/state.py
"""全局状态管理"""

# 配置相关
config_sources = []
current_config = None
api_config = None
openai_client = None

# 会话相关
current_session_id = None
current_session_cache = None

# 录音相关
streaming_asr = None
streaming_asr_pool = None
```

### 4. 更新 main.py

```python
from backend.api.routes import router

app.include_router(router, prefix="/api")
```

## 优点

✅ **代码组织清晰**：每个文件职责单一
✅ **易于维护**：修改某个功能只需要找到对应文件
✅ **便于测试**：可以单独测试每个模块
✅ **减少冲突**：多人协作时不会都修改同一个文件
✅ **符合最佳实践**：遵循 FastAPI 官方推荐的项目结构

## 是否需要重构？

### 现在重构的优点：
- 项目还不算太大，重构成本相对较小
- 后续开发会更轻松

### 暂不重构的理由：
- 当前功能正常工作
- 需要花时间测试确保没有遗漏

### 建议：
如果你计划继续开发新功能，**建议现在重构**。如果项目已经基本稳定，可以暂时保持现状。
