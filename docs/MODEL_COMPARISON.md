# 原始请求模型对比

消息旁「换模型对比」打开原始请求版本列表；可查看提示词与历史、选择目标模型和推理档位，并置顶常用模型。每次结果单独保存，重新打开窗口可查阅，不覆盖原回答、不参与后续聊天上下文。

普通聊天及重新生成的单模型、并行模型调用，均在 SDK 调用前保存请求快照到当前账号的 `request_snapshots/<session>/<question>/<snapshot>.json`。保存的是最终裁剪、场景处理、图片内联之后的 `messages`，包含原始图片数据；不保存供应商 API key。文件权限为 0600。每次请求生成独立版本，不覆盖过去版本。

对比接口从已选快照深拷贝 `messages`、temperature 和 top_p，不读取最新背景、提示词、图片文件或聊天历史，也不按新模型重新裁剪。目标模型、stream 与供应商推理参数按对比选择生成，因此保证消息内容一致而不是全部供应商参数相同。消息数组的 SHA-256 用于验证快照及记录此次输入。目标模型不能处理原始图片或上下文长度时记录失败，不自动删图、截短或改写内容。

对比结果存放在同一问题目录下的 `comparisons/<id>.json`，包含原快照 ID、目标模型、推理参数、响应正文、公开推理内容、耗时、用量和状态。后台任务在关闭弹窗后继续；服务重启会中断尚未完成的任务，重开时显示中断并允许重新提交。成功和失败都持久化。接口先检查当前账号对会话和问题的访问权。旧消息缺少完整快照时禁止精确重放，不从日志猜测复原。

验证：`python -m unittest backend.test.test_model_comparison`。覆盖修改问题/新增历史/修改背景后的原样重放、图片字节、输入哈希一致、结果持久化、原会话不变、缺失快照与失败记录。
