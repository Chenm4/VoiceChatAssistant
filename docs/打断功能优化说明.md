# 打断功能优化说明

## 优化内容

### 1. 自动发送新消息

#### 之前的问题
- 打断后，输入框的内容不会自动发送
- 语音识别的文本只是写入输入框，需要手动再点击发送

#### 现在的行为
- **有新内容时**：打断旧回答 → 自动发送新消息
- **无新内容时**：只打断，不发送

#### 实现逻辑
```javascript
async function handleSendMessage() {
  // 如果正在发送
  if (isSending.value) {
    // 如果输入框有新内容
    if (inputMessage.value.trim()) {
      const newMessage = inputMessage.value.trim()
      stopCurrentResponse()              // 1. 先打断
      await new Promise(resolve => setTimeout(resolve, 100))  // 2. 等待状态重置
      inputMessage.value = newMessage    // 3. 恢复输入内容
      return handleSendMessage()         // 4. 递归调用，发送新消息
    } else {
      // 输入框为空，只打断
      stopCurrentResponse()
      return
    }
  }
  // 正常发送逻辑...
}
```

### 2. 保留已生成内容

#### 之前的问题
- 打断后会删除所有 assistant 消息
- 已经生成的内容也会丢失

#### 现在的行为
- **有内容时**：保留已生成的内容
- **无内容时**：删除空消息

#### 实现逻辑

**单模型场景**
```javascript
if (error.name === 'AbortError') {
  // 检查最后一条 assistant 消息
  for (let i = messages.value.length - 1; i >= 0; i--) {
    if (messages.value[i].role === 'assistant') {
      if (!messages.value[i].content || !messages.value[i].content.trim()) {
        // 没有内容，移除空消息
        messages.value.splice(i, 1)
      } else {
        // 有内容，保留，只移除打字动画
        messages.value[i].is_typing_dots = false
      }
      break
    }
  }
}
```

**多模型场景**
```javascript
if (error.name === 'AbortError') {
  const lastMsg = messages.value[messages.value.length - 1]
  if (lastMsg && lastMsg.is_multi_model) {
    // 检查是否所有模型都没有内容
    const hasContent = lastMsg.models.some(m => m.content && m.content.trim())
    if (!hasContent) {
      // 所有模型都没有内容，移除整个消息
      messages.value.splice(messages.value.length - 1, 1)
    } else {
      // 有内容，保留消息，移除打字动画
      lastMsg.is_typing_dots = false
    }
  }
}
```

## 技术细节

### 1. 递归调用的安全性

**为什么使用递归？**
- 保持代码逻辑清晰
- 避免重复代码
- 确保状态正确

**如何避免无限递归？**
```javascript
if (isSending.value) {
  // 第一次调用：isSending = true，进入这里
  stopCurrentResponse()  // 设置 isSending = false
  return handleSendMessage()  // 第二次调用
}

// 第二次调用：isSending = false，不会再进入上面的分支
// 正常执行发送逻辑
```

### 2. 状态重置延迟

**为什么需要延迟 100ms？**
```javascript
await new Promise(resolve => setTimeout(resolve, 100))
```

- 确保 `stopCurrentResponse()` 完全执行
- 给 Vue 响应式系统时间更新状态
- 避免竞态条件

### 3. 内容检查逻辑

**为什么要检查 trim()？**
```javascript
if (!messages.value[i].content || !messages.value[i].content.trim())
```

- `!messages.value[i].content`：内容为 null 或 undefined
- `!messages.value[i].content.trim()`：内容只有空格

### 4. 多模型内容检查

**为什么使用 some()？**
```javascript
const hasContent = lastMsg.models.some(m => m.content && m.content.trim())
```

- 只要有一个模型生成了内容，就保留整个消息
- 避免部分模型有内容，部分没有的情况

## 边界情况处理

### 情况 1：快速连续打断

```javascript
// 用户快速点击多次
handleSendMessage()  // 第一次
handleSendMessage()  // 第二次（在第一次完成前）
handleSendMessage()  // 第三次（在第二次完成前）
```

**处理方式**：
- 第一次：正常发送
- 第二次：打断第一次，发送新消息
- 第三次：打断第二次，发送新消息

### 情况 2：语音识别中打断

```javascript
// AI 正在生成
// 用户开始语音输入
// 语音识别完成前，用户点击停止按钮
```

**处理方式**：
- 停止按钮：只打断 AI 生成
- 语音识别：继续完成，写入输入框
- 用户可以选择是否发送

### 情况 3：网络延迟

```javascript
// 打断请求发出
// 但服务器还在发送数据
```

**处理方式**：
- AbortController 会立即关闭连接
- 后续数据不会被处理
- 已接收的数据会被保留

## 总结

### 主要改进

1. ✅ **自动发送**：打断后有新内容会自动发送
2. ✅ **内容保留**：打断时保留已生成的内容
3. ✅ **智能判断**：根据输入框状态决定行为
4. ✅ **流畅体验**：无需手动再次点击发送

### 用户体验提升

- 🎤 **语音更流畅**：语音识别后自动发送

- 💾 **内容不丢失**：已生成的内容会保留
- 🚀 **操作更快**：减少手动操作步骤
