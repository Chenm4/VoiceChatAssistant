# 快速测试指南

## 🚀 启动应用

```bash
# 方式1：使用启动脚本
./start.sh

# 方式2：手动启动
# 终端1：启动后端
python backend/main.py

# 终端2：启动前端
cd frontend
npm run dev
```

## 📋 测试步骤

### 测试1：会话配置保存（单模型）

1. 打开浏览器访问 `http://localhost:5173`
2. 点击顶部的 "会话设置" 按钮
3. 选择一个配置源（如 OpenRouter）
4. 选择一个模型（如 `qwen/qwen-2.5-7b-instruct`）
5. 点击 "保存会话配置"
6. 关闭设置面板
7. **再次打开设置面板，检查配置是否保留** ✅

**预期结果**：配置应该保存成功，再次打开时显示之前选择的模型

---

### 测试2：多模型配置和排序

1. 打开 "会话设置"
2. 在模型下拉框中**选择多个模型**（按住 Ctrl/Cmd 点击）
3. 观察下方出现 "模型顺序（从左到右）" 区域
4. **拖拽标签**调整模型顺序
5. 点击标签的 X 可以移除某个模型
6. 点击 "保存会话配置"
7. **再次打开设置，检查多个模型是否保留** ✅

**预期结果**：
- 可以选择多个模型
- 可以拖拽调整顺序
- 保存后再次打开，多个模型都在

---

### 测试3：单模型发送消息

1. 确保当前会话配置为**单个模型**
2. 在输入框输入："你是谁？"
3. 点击发送
4. **观察消息列表**：
   - 用户消息显示
   - AI 回复顶部显示**模型标识徽章**（带颜色） ✅
   - 回复内容正常流式显示

**预期结果**：
- 单个 AI 回复
- 回复顶部显示模型名称
- 不同 provider 显示不同颜色

---

### 测试4：多模型发送消息

1. 打开设置，选择**2-3个模型**
2. 保存配置
3. 发送消息："介绍一下你自己"
4. **观察消息列表**：
   - 应该出现**多条 AI 回复** ✅
   - 每条回复顶部显示**不同的模型名称** ✅
   - 按照设置的顺序依次出现

**预期结果**：
- 有多少个模型就有多少条回复
- 每条回复清晰标识来自哪个模型
- 顺序与设置中的一致

---

### 测试5：UI 改进检查

1. **导航栏**：不应该显示配置源和模型名（已移除）✅
2. **会话列表**：消息数量显示为 "X 条消息"，不是图标 ✅
3. **折叠按钮**：在侧边栏**底部**，不是和新建按钮在一起 ✅
4. **新建对话按钮**：是**蓝色**（Element Plus 主题色），不是紫色 ✅
5. **所有按钮**：都使用 Element Plus 风格 ✅

## 🐛 常见问题排查

### 问题1：保存配置后再次打开还是单模型

**检查**：
```bash
# 查看后端日志，确认配置是否保存
# 应该看到类似：配置已更新: session=xxx, models=[...]

# 或手动检查
curl http://localhost:8000/api/sessions/{session_id}
# 检查返回的 session_config.models 是否是数组
```

**解决**：
- 刷新页面重试
- 检查浏览器控制台是否有错误
- 查看后端是否正常运行

---

### 问题2：多模型发送后只有一个回复

**检查**：
```bash
# 查看后端日志
# 应该看到：🚀 开始流式调用: models=[...], parallel=True

# 检查当前会话配置
curl http://localhost:8000/api/sessions/{session_id}/config
```

**可能原因**：
- 会话配置未保存成功
- 前端读取配置失败
- 后端未正确检测到多模型

---

### 问题3：模型标识不显示

**检查**：
- 打开浏览器开发者工具 → Network → 查看 `/api/chat` 响应
- 检查消息对象是否包含 `model_info` 字段
- 刷新消息列表（发送消息后会自动重新加载）
