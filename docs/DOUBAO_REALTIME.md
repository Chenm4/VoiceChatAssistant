# 豆包文字与录音提交

主聊天页使用同一个麦克风入口：开始后由现有后端录音和 ASR 收音，停止后才将完整识别文字发送给已选 LLM，同时将同一份已保存录音提交给豆包。麦克风设备、提示词、场景和背景均复用现有设置。悬浮窗打开时启用豆包输出，关闭时取消其请求，不影响主录音和 LLM。

录音中悬浮窗仅显示共享 ASR 草稿，不连接豆包。点击麦克风停止或 Alt+E 停止才提交；单次 Esc、录音超时、页面隐藏、切换会话及卸载只停止，不触发模型回答。启动下一次录音会取消上一次豆包生成。

当前 Seeduplex 3.0 不支持 response.create（真实接口测试返回 unknown event name）。因此使用“停止后提交完整录音”，不是伪造手动 VAD 参数。供应商要求以 20ms 实时节奏上传文件，豆包回复可能晚于普通 LLM。完整识别问题也注入本轮 instructions，避免录音内停顿导致只理解半个问题。

后端校验录音属于当前会话且位于 data/voices，格式为单声道 16kHz PCM16，最长五分钟。原先浏览器采音、音频处理器及实时推流入口已经删除；WS 接受带 session_id 和 text 的文字问题；提交录音时另带 audio_file。文字输入在本地通过 macOS 的 say / afconvert 转成 16kHz PCM 文件，再提交给同一语音模型；不播放声音，不读取麦克风，临时文件在处理后删除。打开悬浮窗后，输入框发送文字会同时提交普通模型和豆包；录音提交只发送原始录音，避免重复提交。

## 无播报

前端只有文本 WebSocket 客户端，无 AudioContext、音频解码、播放队列、SpeechSynthesis、文字播报或音色选择；后端不解码、不转发上游音频。上游协议仍要求 audio.output/voice 必填，供应商仍可能生成音频并计费；这些音频直接丢弃，不播放。screenCapture.js 的 video.play() 用于无声屏幕截图视频帧，不是语音播报。

悬浮窗仍支持全文左键拖动、滚轮浏览、暂停自动跟随、收起和透明度调整。提示词通过 compose_session_system_prompt 与 render_session_user_prompt 复用。

验证：后端单元测试覆盖提交前不上游、完整录音提交、丢弃音频、拒绝旧实时入口和非本会话文件；前端测试覆盖显式提交及拒收二进制输出。官方 Demo 录音真实接口验证获得中文文字回复和 complete。

```sh
.venv/bin/python -m unittest backend.test.test_doubao_realtime -q
node --test frontend/test/doubaoRealtime.test.js
cd frontend && npm run build
```

## 统一右键控制

聊天页面任意位置（包含输入框、悬浮窗和麦克风按钮）右键使用同一个录音开关，同时阻止默认与组件右键菜单。右键停止仍沿用手动提交规则，向已选 LLM 和豆包提交；Esc 保留草稿。离开聊天页后移除监听，不更改浏览器或操作系统设置。

启动/提交时按钮显示进度，避免重复触发。服务启动与后台实例预热提前加载降噪依赖；音频设备由工作线程打开，接口在设备实际就绪时返回成功。预热不采音、不连接 ASR。

## 麦克风与 USB 连续切换

标题栏「输入设置」分别选择麦克风和声卡输入。麦克风默认优先使用内置麦克风，声卡默认优先选择 USB 声卡并排除摄像头麦克风。已有手动选择会保留，可点击「恢复默认设备」重新选择。会话设置仍可将右键改为拍照。

识别中点击另一入口调用 `/recording/switch-input`，保留 ASR 连接和累计文字。麦克风入口使用双路混音，右键入口使用声卡单路；切换时清空第二路缓冲，避免重放旧音频。

## 双路混音录音

设置区显示「默认模式：双路混音」及两路设备名称，录音按钮持续显示模式。选到同一设备时明确提示实际为单路；右键识别期间显示「声卡单路」。

输入设置中的「麦克风」选择本机麦克风，「声卡 / 右键」选择 USB 声卡输入。点击麦克风按钮同时采集这两个设备，将麦克风降噪后的 PCM 与声卡 PCM 按各 50% 音量混合，送入同一 ASR 连接并保存同一份 WAV。两项选择同一设备时只采集一次，不降低音量。右键仍为声卡单路；录音中点击另一入口继续原识别连接并切换模式。

混音以选中麦克风的音频块为节拍，第二路最多缓冲两个块，丢弃过期音频，缺少音频块时补静音，避免音频时长翻倍和积累延迟。这是块级对齐，不是硬件采样时钟同步。混音启动时第二路无法打开会报错；运行中任何一路采集报错会停止录音。此功能不包含声学回声消除，外放被麦克风再次收录时仍可能影响识别。


## 双击 Esc 清空输入框

350 毫秒内连续按两次 Esc，仅清空输入框文字，不停止录音、不清除后端识别或音频。前端记住清空时的累计识别文字长度，之后仅显示该位置之后的内容；停止录音的文字结果也使用相同显示边界。识别服务改写清空之前的临时文字时，字符边界可能偏移。单次 Esc 保留停止识别、不发送的行为，延后 350 毫秒执行以区分双击；长按产生的重复键事件不算双击。


## 停止识别时延

手动停止时，从后端收到停止调用起为最终识别结果预留最多 1 秒；停止采集和保存 WAV 所用时间会扣除这个等待预算。收到最终结果立即返回，否则使用已有实时文字；没有文字则返回识别失败，不继续轮询。网络连接关闭在后台执行，不阻塞消息发送。录音线程退出和停止接口共同确保尾部音频与唯一结束标记送达发送队列，避免服务端一直等待后续音频。文件写入和硬件收尾仍需本地处理时间，1 秒是识别结果等待预算，不是所有异常硬件情况下接口总耗时的保证。


## 左键与右键采集模式

输入设置分别为麦克风按钮和右键提供「双路混音 / 只录麦克风 / 只录声卡」三个模式，记住各自选择。默认麦克风按钮为双路混音，右键为声卡单录。两路设备仍由麦克风和声卡选择器共同指定；切换入口时按目标入口的模式切换同一 ASR 会话。模式在录音期间锁定，避免界面与实际采集状态不一致。
