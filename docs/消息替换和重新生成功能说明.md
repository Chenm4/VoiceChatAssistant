# 消息替换和重新生成功能说明

## 功能概述

此功能允许用户在会话中修改某条消息的内容，并让模型基于新的消息内容重新生成响应。这对于以下场景特别有用：

- 发现某条消息有错误或不够准确
- 想要调整问题的表述
- 希望模型重新回答某个问题

## 功能特点

### 1. 智能消息替换
- 可以修改任何用户消息
- 自动删除该消息之后的所有子消息
- 保留该消息之前的所有对话历史
- 基于新的消息内容重新生成响应

### 2. 支持多种使用方式
- **方式一**：点击用户消息旁的"编辑并重新生成"按钮（旋转箭头图标）
- **方式二**：直接编辑消息后选择"保存并重新生成"

### 3. 支持多模型并行
- 如果会话配置了多个模型，会同时向所有模型发送请求
- 流式显示每个模型的响应
- 支持单模型和多模型模式无缝切换

## 使用方法

### 方法一：直接重新生成

1. 找到要修改的用户消息
2. 将鼠标悬停在消息气泡上，显示操作按钮
3. 点击"编辑并重新生成"按钮（旋转箭头图标 🔄）
4. 在编辑框中修改消息内容
5. 点击"保存并重新生成"按钮（绿色勾号）

### 方法二：编辑后决定是否重新生成

1. 点击消息旁的"编辑"按钮（铅笔图标 ✏️）
2. 修改消息内容
3. 如果只想保存修改，点击"保存"
4. 如果想重新生成响应，点击旁边的"编辑并重新生成"按钮

## 后端实现

### 新增数据模型

```python
class RegenerateMessageRequest(BaseModel):
    """重新生成消息请求"""
    message_id: str  # 要替换的消息ID
    new_content: str  # 新的消息内容
    model: Optional[str] = None  # 可选：指定使用的模型
```

### 新增 API 接口

**接口地址**：`POST /api/sessions/{session_id}/messages/{message_id}/regenerate`

**请求体**：
```json
{
  "message_id": "msg_abc123",
  "new_content": "这是修改后的消息内容",
  "model": "gpt-4"  // 可选，不指定则使用会话配置
}
```

**响应格式**：Server-Sent Events (SSE) 流式响应

```
data: {"type": "content", "data": "响应内容片段"}
data: {"type": "done"}
```

### 处理流程

1. **验证和加载**
   - 验证会话是否存在
   - 验证消息是否存在
   - 验证消息是否为用户消息

2. **更新消息**
   - 更新目标消息的内容
   - 更新消息时间戳

3. **删除子消息**
   - 递归收集目标消息的所有子消息 ID
   - 从会话中删除这些消息
   - 清空目标消息的 children_ids

4. **构建消息历史**
   - 使用 `build_message_path()` 函数构建从根到目标消息的路径
   - 包含系统提示词（如果有）

5. **生成新响应**
   - 确定使用的模型（请求指定 > 会话配置 > 全局配置）
   - 支持单模型和多模型并行
   - 流式返回响应内容

6. **保存结果**
   - 创建新的 assistant 消息
   - 更新目标消息的 children_ids
   - 保存会话到磁盘

## 技术细节

### 树形消息结构

消息采用树形结构存储，每条消息包含：
- `id`: 消息唯一标识
- `parent_id`: 父消息 ID
- `children_ids`: 子消息 ID 列表
- `content`: 消息内容
- `role`: 角色（user/assistant/system）

这种结构支持：
- 分支对话
- 消息版本管理
- 精确的历史追溯

## 错误处理

### 前端错误处理
- 请求失败：显示错误通知
- 网络中断：自动清理临时消息
- 超时：60秒超时限制

### 后端错误处理
- 会话不存在：返回 404
- 消息不存在：返回 404
- 非用户消息：返回 400
- API 调用失败：流式返回错误信息

## 已知限制

1. **只能重新生成用户消息**：不支持直接修改 AI 响应
2. **会删除后续消息**：修改某条消息后，其之后的所有对话都会被删除
3. **不支持撤销**：删除的消息无法恢复（除非有备份）

## 未来改进方向

1. **版本管理**：保留消息的历史版本
2. **预览模式**：在真正删除前预览影响范围
3. **选择性保留**：允许用户选择保留某些后续消息
4. **批量重新生成**：支持一次修改多条消息
5. **AI 响应编辑**：支持直接修改和重新生成 AI 响应
